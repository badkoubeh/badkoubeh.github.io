What I'm working on

Two things — and they're the same thing.

The question

Does RL post-training actually widen a policy's robustness margin, or does it improve the average case while pushing failures into the tail? I think it's the most interesting open question in post-training, and it's currently unanswerable — because the field has no standard way to measure a margin in the first place.

The tool

So I'm building that first: an open, model-agnostic harness for estimating failure thresholds, so that anyone can ask the question of their own system instead of taking my word for the answer on mine.

The gap

Where does it break, and how sure are we?

Open-weight driving and robotics vision-language-action models are being deployed with no standard way to say where they fail. Papers plot accuracy against perturbation severity and stop there; nobody reports the failure threshold itself with an interval around it. Toxicology and psychophysics solved this decades ago with dose-response modelling — ED50 estimation, profile-likelihood intervals, Fieller intervals on the ratio of two thresholds — and essentially none of it has been imported into ML robustness evaluation.

I'm building that import as open infrastructure: a model-agnostic statistics package and an evaluation harness that degrades a policy's inputs along physically-calibrated axes and returns σ*, a threshold in real sensor units, with a confidence interval.

Projects

Open tools, one measurement.

marginkit

The measurement primitive

Model-agnostic dose-response threshold estimation. Feed it (severity, outcome) observations; get back σ* with a confidence interval, right-censoring handled, monotonicity checked, and a Fieller interval when you need to test whether one failure mode has a lower threshold than another. No GPU, no ML dependency. It already estimates robustness margins for a classical PID controller on a 6-DOF rocket in zeta-bench.

marginbenchIn development

The harness

Declarative degradation axes calibrated against named IMU and GNSS datasheets, model adapters behind a single interface, and an auto-generated robustness report card. Ego-state noise, bias/drift, and observation staleness — parameterised in metres, degrees, and milliseconds, not arbitrary σ multiples or conventional ε-balls.

NVIDIA Alpamayo

The first application

An open-weight reasoning VLA that emits a chain-of-causation explanation alongside a trajectory. The question: does the explanation stop tracking the trajectory at a lower input-degradation severity than trajectory quality itself degrades? If it does, the interpretability guarantee fails exactly when you most need it. This is an open question I'm measuring, not a result I'm reporting.
